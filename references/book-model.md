# 书本模型

书本模型是对指定文本的可核对压缩，不是随意的人物卡。只记录足以支持学习对话的内容。

## 超长文本工作模型

若授权范围超出当前上下文，必须先取得用户对写入路径的明确同意，再创建工作模型。每读完一批就原子更新：

- `coverage`：已读、未读、缺失或不可读范围；
- `concepts`：概念与稳定位置；
- `claims`：主张、前提、反对意见和证据编号；
- `tensions`：冲突、限定与待核对项；
- `next_batch`：下一批明确范围。

每批开始前读取该模型，并回到相关原文核对即将使用的证据。工作模型完成的条件是授权范围全部归入覆盖表，关键主张有证据位置，缺口明确列出。未满足前只能进行已覆盖章节对话，不能声称完成全书建模。

## 1. 文本身份

```yaml
title:
author:
edition:
translator:
language:
source_path:
coverage:
readability_issues:
```

- `coverage` 写清全书、卷、章或页码范围。
- 译本存在时保留译者信息；关键术语若有歧义，记录原文词或多个译法。
- 扫描、OCR、缺页或乱码会影响判断时列出位置。

## 2. 核心问题

用一句普通话写出本书真正试图回答的问题。不要用主题标签代替问题。

差：`本书讨论正义。`

好：`一个人为什么应当正义，即使不正义似乎更有利？`

## 3. 概念表

每个概念只记录：

```text
概念｜作者如何使用｜与日常用法的差别｜首次关键位置｜易混概念
```

定义必须来自明确文本或标为综合。不要从词典替作者定义。

## 4. 主张与论证链

每项使用稳定编号：

```text
C1 主张：
证据位置：
理由：P1 + P2 -> C1
依赖：
作者给出的例子：
反例或压力点：
置信度：明确 / 综合 / 不足
```

主张不是章节摘要。只保留会影响其他观点、容易被误解或适合追问的论证节点。

## 5. 反对意见

```text
O1 反对意见：
提出者：作者 / 角色 / 作者引用的他人 / 模型构造
作者回应：
回应是否完整：
文本位置：
```

模型自己构造的反例必须标明，不能伪装成书中的反对意见。

## 6. 内部张力与边界

记录：

- 两处看似冲突的表述；
- 只在某些条件下成立的结论；
- 作者承认但没有解决的问题；
- 不同角色、章节或时期的立场变化；
- 译法可能造成的分歧。

不要为了得到整齐体系而抹平张力。

## 7. 作者推理画像

只记录文本支持、且有助于对话的特征：

- 常从定义、例子、分类、类比还是反例推进？
- 先拆概念还是先追问后果？
- 哪类答案会被作者视为答非所问？
- 作者如何承认不确定性？

不要编造口头禅、私人习惯、情绪或生平。

## 8. 证据索引

每个重要定位包含：

```text
E1｜章节/页码/段落/行范围｜短提示语｜支持 C1/P2/O1
```

不同版次页码不一致时，优先给卷、章、节、段首短语等稳定定位。PDF 页码需区分文件页码和书本印刷页码。

## 9. 学习地图

按依赖而非目录排序：

1. 必须先懂的概念；
2. 基础论证；
3. 最强反对意见；
4. 应用或现实后果；
5. 仍开放的问题。

里程碑只组成无序集合，不预写固定提问链。每一步配置一个能区分“记住结论”和“理解理由”的候选问题；实际下一问必须根据学习者上一答动态选择。
